## Must fix
- `must-fix` — **`src/ui/PreviewMode.tsx:29`** — `PreviewPhoto` is a line-for-line copy of `CellPhoto` at `src/ui/SpreadView.tsx:44-62`. Both have the same `usePreviewUrl(meta.id, 'full')`, the same `if (!url) return null`, the same `sourceRect` call, the same four percentage styles and the same `cell-photo` class (`styles.css:78`). These two components must change together. The preview exists to show what the editor will print, so any later change to how a crop renders (a rotation, a different preview size, an export-phase tweak) applied in one place makes the preview disagree with the editor without any error.
  → Export `CellPhoto` from `SpreadView.tsx` (or move it to its own module under `src/ui/`) and render it in `PreviewMode`. Delete `PreviewPhoto`. Nothing differs between the two copies, so this needs no adaptation.

## Should fix
- `should-fix` — **`src/ui/SettingsDialog.tsx:19`** — the ivory swatch hardcodes `'#f4efe6'`, which duplicates `DEFAULT_SETTINGS.background` at `src/model/types.ts:66`. The radio's `checked` is a string comparison (`s.background === b.colour`, `:88`). If someone changes the default, every new album opens with no background radio checked.
  → Use `DEFAULT_SETTINGS.background` for the ivory entry, or move the three-colour palette into the model and make `DEFAULT_SETTINGS` refer to it.
- `should-fix` — **`src/ui/PreviewMode.tsx:86`** — `album.spreads[index]` reads the raw state index. `last` is only applied when the state is first set (`:60`) and inside `go` (`:67`). `Editor.tsx:43` clamps the index at render time (`Math.min(spreadIndex, album.spreads.length - 1)`), and the preview does not. This matters because the editor's Ctrl+Z/Ctrl+Y listener (`Editor.tsx:46-62`) stays mounted during preview, and the preview's capture listener stops only arrows and Escape (`:74-80`). Example: preview the last spread, then press Ctrl+Z to undo an "add spread". `spread` becomes `undefined`, `PreviewMode` returns `null` at `:87`, and the screen is empty with no close button. Only Escape still works.
  → Follow `Editor.tsx:43`: compute `const at = Math.min(index, last)` and render from `at`, including in `onClose(at)` and the `data-spread-index`. Alternatively, also swallow Ctrl/Cmd+Z/Y in the preview's capture listener. The first option is the one that matches the neighbour.
- `should-fix` — **`src/ui/SettingsDialog.tsx:42`** — the coalesce key is the same for the whole life of the store (`settings:${field}`). Every other coalescing call site in `src/ui` creates a fresh key for each gesture: `CellToolbar.tsx:34` + `:59`, `SpreadView.tsx:118`, `:151`, `:251`. The static key has two effects. (1) Turning guides off and then on again (two clicks) becomes one undo step with no net change, so the next Ctrl+Z appears to do nothing. The same happens with book start (single-right and back). (2) Two edits to the same field in separate dialog openings merge into one step if nothing else was dispatched in between. Opening the preview dispatches nothing.
  → Keep the `settings:<field>` prefix and add a suffix for each gesture, the way `CellToolbar.tsx` does it: a `useRef<string | null>`, set with `??=` to `` `settings:${field}:${performance.now()}` `` in the input handler, and reset to `null` in `onChange`. Unlike the slider, this dialog has several controls, so the key must include the field name. One ref is enough, because moving focus from the number input to a radio fires the input's `change` first. Effect per control: a radio or checkbox gets one step per click, because `change` fires on every click. A number field gets one step per typing run, which ends on blur or Enter, and one step per spinner click.
- `should-fix` — **`tests/e2e/settings.spec.ts`** — no test covers the preview's not-printed side (`PreviewMode.tsx:142-149`, `preview-blank-*`), although the phase goal names it. If someone deletes the `blank` overlay, or flips `left`/`right` in it, every test still passes.
  → Add a case: check `setting-book-single-right`, open the preview, and expect `preview-blank-left` attached on spread 1 and `preview-blank-right` absent.

## Suggestions
- **`src/ui/PreviewMode.tsx:147`** — the width of the left blank side is `TRIM_W - FOLD_X`, which is correct only because the fold is at the centre. `SpreadView.tsx:311` uses `fold` for the left side and `canvas.w - fold` for the right side. → `width: px(side === 'left' ? FOLD_X : TRIM_W - FOLD_X)`.
- **`src/ui/PreviewMode.tsx:15`** — `BAR_PX = 64` guesses the height of `.preview-bar` / `.preview-nav` from CSS (`min-height: 48px` + `gap: 8px`, `styles.css:164-168`). Nothing measures the bars, so if the bar wraps on a narrow screen or a button grows (`font-size: 22px` + padding at `:168`), the stage overflows. Also, the editor sizes by measuring a host element, and the preview sizes from the window, so the UI now has two scaling conventions. → Reuse `useScale` from `SpreadView.tsx:25-42`. All of it carries across: it measures a host's `clientWidth`/`clientHeight` with a `ResizeObserver`, takes `min(w / cw, h / ch)`, falls back to `w / cw` when the height is 0 (harmless here), and runs again on `[cw, ch]`. To use it, export it, and put a `flex: 1; min-height: 0` host between the bar and the nav for it to measure.
- **`src/ui/PreviewMode.tsx:115`** — `index === 0 ? strings.cover : strings.spreadPosition(index, last)` repeats `Editor.tsx:123` exactly. These two must change together, because both are the user-visible label of spread *i*. → A `spreadLabel(index, total)` entry in `strings.ts`, used by both.
- **`src/ui/styles.css:165`** — `background: #2a2622` is the value of `--ink` (`:3`). → `var(--ink)`.
- **`tests/e2e/settings.spec.ts:10`** — the spec declares a local `DevWindow` type, but `App.tsx:13-17` already declares `Window.__store` globally, and `spread.spec.ts`, `dnd.spec.ts` and `shell.spec.ts` use `window.__store!`. (`crop.spec.ts` also has a local type, so two conventions already exist.) → Use the global declaration.
- **`tests/e2e/settings.spec.ts:136`** — the "swipe" test sends mouse pointer events on both projects. The name says swipe, but the test does not drive a touch path (`pointerType: 'touch'`, browser `pointercancel`). AC-6.14 plans a real touch swipe, so call this one a drag in the name. Other missing cases are cheap to add: typing `25` into `setting-gap` (if someone removes the clamp at `SettingsDialog.tsx:48`, no test fails), ArrowRight on the last spread staying put, and Escape closing the settings dialog.
