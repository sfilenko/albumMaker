## Should fix
- `should-fix` — **`src/model/layout.ts:65-66`** — `toCanvas` computes the canvas edge inline as `TRIM_W + 2 * b` and `TRIM_H + 2 * b`. The scaffold already has that definition in `canvasSizeMm` (`src/model/units.ts:14-15`, tested in `tests/unit/units.test.ts:10`). Two definitions of "canvas size" will drift: if bleed handling changes in `units.ts`, for example for export, cells will stop reaching the canvas edge and no layout test will show that the cause is the second copy.
  → In `toCanvas`, take `const c = canvasSizeMm(b)` and compare against `b + TRIM_W` / `b + TRIM_H` as before. Set `x2 = c.w` and `y2 = c.h`. The trim-edge comparison (`b + TRIM_W`) stays as it is, because it is the trim edge and not the canvas edge.

- `should-fix` — **`src/model/album.ts:1-2`** — the module header promises "a new Album with a new updatedAt, or the same Album when nothing changes". Several operations do not keep that promise. `moveGutterOp` (`album.ts:115-117`) always goes through `mapSpread` → `touch`, even when `moveGutter` returns the input `layout` unchanged on its no-op paths (`layout.ts:117`, `:121`, `:124`, `:126`, `:133`, `:144`). `renameAlbum` (`:146`) and `updateSettings` (`:151`) touch on an identical name or an empty patch. The functions that do keep the promise (`removeSpread:130`, `moveSpread:137-139`, `addPhotos:61`, `setCell:35`) show the intended pattern. A later phase that reads this header as a contract (for example `next === a` to skip an undo entry or an autosave) will record no-op entries.
  → Make the no-op cases return `a`. In `moveGutterOp`, call `moveGutter` first and return `a` when the result `=== s.layout`. Return `a` in `renameAlbum` when `name === a.name`. Alternatively, narrow the header to name the operations that keep the promise. Do one of the two, so that the comment and the code agree.

- `should-fix` — **`tests/unit/layout.test.ts:78-84`** — the only test with a non-root `GutterRef.path` does not use one. `gutters` pushes a parent's strips before it recurses (`layout.ts:88-98`), so `.find((g) => g.ref.side === 'left')` on `g8` returns the `cols` border at `path: []`. As a result, the recursive branch of `replaceAt` (`layout.ts:104-109`) and the path descent in `moveGutter` (`layout.ts:120-125`) never run in a test. Example regression: `replaceAt` writes `sizes` one level too high or on the wrong child, and every test still passes. Also, no test covers `pages` mode with a non-zero `marginMm` (`layout.ts:22`, `:26`). Example regression: the margin is applied at the fold side of the right page.
  → Add a case that picks a horizontal gutter (`g.orientation === 'h'`, `path: [0]`) on `g8` and asserts that only cells 0 and 1 change. Add a case for `two` with `marginMm: 10` that asserts both rects.

## Suggestions
- **`src/model/crop.ts:7`** — `MM_PER_INCH = 25.4` is a private constant. `src/model/units.ts:3` writes the same value as a bare `25.4` in `PX_PER_MM`. → Export `MM_PER_INCH` from `units.ts`, use it in `PX_PER_MM`, and import it in `crop.ts`. `units.ts` is the module whose header says it owns mm/pixel conversion.
- **`src/model/crop.ts:9`** — `clamp` is private. The same `Math.min(Math.max(v, lo), hi)` form is written inline at `src/model/layout.ts:134`, `src/model/album.ts:121` and `src/model/album.ts:138`. → Move `clamp` to `units.ts` (or a small `math.ts`) and use it at all four sites. This is a style point, not drift risk: the expression is trivial.
- **`src/model/layout.ts:140`** — `n as typeof target` casts away the `cell` case. The cast is sound today only because the descent at `:120-126` has already checked the path. → Narrow instead: `(n) => (n.kind === 'cell' ? n : { ...n, sizes })`. Then the type proves it and needs no help from the earlier walk. Similarly, `src/model/templates.ts:55` has `columns(t.spread)!`, which hides the `spread: []` case. A local `if (!root) throw` would match the `unknown template` throw at `:53`.
- **`src/model/pages.ts:64`** — `sideIsPrinted` rebuilds `printedPages(a)` for every side of every cell, although `printWarnings` already called `printedPages(a)` at `:54`. → Compute the pages once at `:54`, build a `Set` of `${spreadId}:${side}`, and test membership. Keep `sideIsPrinted` as the exported single-query form.
- **`src/model/pages.ts:11,13`** and **`src/model/layout.ts:81,84`** — each file writes an inline object return type twice (`{ page; spreadId; side }` and `{ ref; orientation; rect }`). → Name them (`PrintedPage`, `Gutter`) next to `PrintWarning`. Also, `Side` (`pages.ts:7`) duplicates the `'left' | 'right'` part of `GutterRef['side']` (`types.ts:61`). `types.ts` says it holds the shared types, so `Side` could live there, and `GutterRef.side` could become `Side | 'spread'`.
- **`src/model/album.ts:79,109`** — `{ photoId, crop: { ...EMPTY_CROP } }` is built twice, next to the `emptyCell` factory at `:14`. → A `cellWith(photoId: string | null)` factory would cover all three.
- **`tests/unit/album.test.ts:78`** — the test sets a crop by rebuilding `spreads` by hand, although `setCrop` (`album.ts:94`) exists. No test imports `setCrop`, `moveGutterOp` or `renameAlbum`. → Use `setCrop` here: the test then covers it at no extra cost. Also add one `addPhotos` case for the duplicate-id filter at `album.ts:59-61`. Example regression: a re-import of the same folder doubles `photos`.
- **`tests/unit/album.test.ts:138`** — the title says "every operation", but the test checks two. → Rename the test, or loop over the exported operations.
- **`tests/unit/crop.test.ts:37-40`** — `panCrop` asserts only the direction (`cx < 0.5`). A wrong mm-to-pixel scale at `crop.ts:50-51` (for example, `photoW` where `sw` belongs) still passes. → Assert the value: with `w: 100` and `sw = 4000`, a 10 mm drag gives `cx = 0.5 - 400/6000 ≈ 0.4333`.
- **`tests/unit/pages.test.ts:59`** — `expect(w!.kind === 'low-dpi' && w!.dpi)` passes `false | number` to `toBeCloseTo`. → Narrow with a type-guard `find((x): x is Extract<PrintWarning, { kind: 'low-dpi' }> => x.kind === 'low-dpi')` and assert `w.dpi`.
