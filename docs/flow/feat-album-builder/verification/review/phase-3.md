# Review: feat-album-builder phase 3

_Reviewed 2026-10-28 · 9 files · `df:devflow-reviewer` · verdict at review time: pass_

## Should fix
- `should-fix` — **`src/photos/import.ts:113-131`** — the `try` covers decode, EXIF, encoding and both `putPreview` writes, and the bare `catch` turns every failure into "skipped by name". The docstring (line 98) promises `skipped` only for files the browser cannot decode. When storage is full, `putPreview` throws `QuotaExceededError`, and each photo goes to `skipped` as if it were a bad file. The user gets no "storage full" signal. Also, if the `full` write succeeds and the `thumb` write fails, the `full` copy stays in `previews` under an id that no album lists, so `deleteAlbum` (`src/storage/db.ts:57-58`) never deletes it. The storage layer around this module treats quota as a real error that must reach the caller: `createAutosaver` sends it to `onError` (`src/storage/autosave.ts:25-29`), and `tests/unit/storage.test.ts:88` tests that case.
  → Put only `createImageBitmap` (line 114) in the try/catch that pushes to `skipped`. Let `putPreview` and `scaledJpeg` errors propagate out of `importFiles`. `readTakenAt` already catches its own errors (line 73), so it needs no outer guard.

- `should-fix` — **`src/photos/import.ts:41-44, 59-60`** — "the user cancelled" now has a second meaning in this codebase. `pickFolder` returns `null` on `AbortError`, and `pickFiles` resolves `[]` on `cancel`. The only other picker module, `src/storage/layoutFile.ts`, rejects with `DOMException('…', 'AbortError')`. It does this when the input fires `change` with no file (line 81) and on `cancel` (line 83). It also lets the native picker's `AbortError` propagate uncaught from `saveLayoutFile` (line 55) and `openLayoutFile` (line 89). So the UI phase must handle cancel two ways, depending on which picker it called. `pickFolder` also returns `null` for two different reasons: "no picker in this browser" and "cancelled". The caller cannot tell whether to fall back to `pickFiles`.
  → Use the `layoutFile.ts` convention: (1) in `pickFiles`, reject with `new DOMException('no file chosen', 'AbortError')` on `cancel`, and also on a `change` that has zero files, as `pickWithInput` does at line 81. (2) In `pickFolder`, delete the catch at lines 41-44 so the native `AbortError` propagates. One part of the precedent does not carry over: `layoutFile.ts` falls back to an `<input>` inside the same function when the picker is absent (lines 66-72, 89-91). `pickFolder` cannot do that, because its result holds a `FileSystemDirectoryHandle` that an input cannot provide. So keep `return null` at line 37, and after this change `null` means only "no folder picker".

- `should-fix` — **`tests/unit/match.test.ts:52-60`** — the only `ambiguous` test covers one photo with two candidates (`hits.length > 1`). It does not cover the other branch of the condition at `src/photos/match.ts:52`: two photos whose only candidate is the same one (`claims.get(hits[0]) !== 1`). Suppose someone drops `&& claims.get(hits[0]) === 1`. Both photos then match the same candidate index, because the `hits` were computed before line 54 adds the candidate to `used`. Every test still passes, and export then uses one file for two different photos.
  → Add a test: two wanted photos with the same name and dimensions but different sizes, and one candidate with that name and dimensions. Expect `ambiguous` to contain both ids and `matched.size` to be 0.

- `should-fix` — **`src/photos/import.ts:115`** — no test passes `ids`. `ids?.get(file) ?? newId()` keeps the cell references of a layout from another device when its photos are imported again. If this line becomes `newId()`, the re-imported photos lose their place in the layout, and no test fails. The unit tests import only `isAccepted` and `mapLimit`, and the e2e calls `importFiles` through the harness input with no `ids` (`src/harness.ts:23`).
  → Add an e2e case that uses the exposed `window.__importFiles` (`src/harness.ts:15`, which no test calls now). Build the `File` objects in the page, pass `new Map([[file, 'keep-me']])`, and assert `metas[0].id === 'keep-me'` and `__previewSize('keep-me', 'thumb') > 0`.

## Suggestions
- **`src/photos/import.ts:8` and `:58`** — two separate lists of the accepted types: the `ACCEPTED` regex and the `input.accept` string. If someone adds a type such as `.avif` to one list only, the picker and the filter stop agreeing, and files that the picker offers go silently into `skipped`. → Derive both from one `const EXTENSIONS = ['jpg', 'jpeg', 'png', 'webp']` (and the MIME list next to it).
- **`src/photos/match.ts:16-25`** — the four levels are anonymous lambdas. The only explanation is "the plan's Decision Log", which a reader of the source cannot open. The third level also has a three-part date condition (line 23) with no name. → Give each level a name (`sameNameAndSize`, `sameNameAndDimensions`, `sameStemAndRatio`, `sameDateAndRatio`), and put the date clause in a helper `datesAgree(w, c)`. State the order rationale in the code, not in a plan reference.
- **`src/photos/match.ts:4`** — `Candidate` repeats five fields of `PhotoMeta` (`src/model/types.ts:38-46`), and the two types must stay the same for the ladder to compare them. `Pick<PhotoMeta, 'name' | 'size' | 'width' | 'height' | 'takenAt'>` makes the link explicit. No file in `src` uses `Pick` yet, so this is a preference, not a convention.
- **`src/photos/import.ts:32`, `src/photos/originals.ts:6-9`, `src/storage/layoutFile.ts:17-25`** — three different ways to type the File System Access members that are not in the DOM typings: an intersection type plus a cast, an `extends` interface plus a cast, and a separate interface plus `as unknown as`. The comments use the same words, but the code differs. → Choose one form (the intersection in `import.ts` needs no `unknown`), and use it in all three files.
- **`src/harness.ts:22-25`** — if `importFiles` rejects, `data-state` never becomes `done`, and the e2e (`tests/e2e/import.spec.ts:19`) waits 30 s and then fails with a timeout that does not give the cause. → Catch the error, set `root.dataset.state = 'error'`, and store the message so that the test can show it.
- **`tests/e2e/import.spec.ts:29-36`** — the previews are only checked to be larger than 0 bytes. If someone swaps the `PREVIEW_EDGE` values (`import.ts:10`) or removes the scaling in `scaledJpeg`, the test still passes. → In the page, decode each preview with `createImageBitmap` and assert that its long edge is 1600 or less for `full` and 320 or less for `thumb`.
- **`src/photos/originals.ts:28-42`** — `getOriginal` has no test. It checks memory first, then the stored folder, and matches by name and size. The fixtures `tests/fixtures/dup-a/IMG_0001.jpg` and `dup-b/IMG_0001.jpg` exist for this kind of case. If the size check at line 36 is lost, export takes the wrong file of the same name, and no test fails. → Unit-test it with `vi.mock('../../src/storage/db')` that returns a fake directory handle (a real handle with methods cannot be put into fake-indexeddb).
