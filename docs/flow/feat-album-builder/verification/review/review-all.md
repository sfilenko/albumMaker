## Must fix
- `must-fix` — **`src/ui/ExportDialog.tsx:42`** — `candidate()` is a second copy of `describe()` at `src/ui/RelinkDialog.tsx:16`, and the two copies already differ. `describe` reads the capture date with `readTakenAt` (its comment says why: "the same reader as import, so the ladder compares dates in one form"). `candidate` always sets `takenAt: null`. Both feed `matchPhotos`. With `takenAt: null` on every candidate, ladder level 4 (`src/photos/match.ts:24`) can never match in the export, and the date guard of level 3 (`match.ts:23`, `c.takenAt === null || ...`) always passes. So the export accepts a stem-and-ratio match that relink would reject because the dates differ, and it finds no match for a renamed original that relink finds by date. One question ("which file is this photo?") now has two answers that depend on the dialog.
  → Move `describe` (the version with `readTakenAt`, the try/catch around `createImageBitmap`, and the `width: 0, height: 0` fallback) to `src/photos/match.ts` or `src/photos/import.ts` as an exported `describeFile(file): Promise<Candidate>`. Call it from both dialogs and delete `candidate`. The `mapLimit(files, DECODE_LIMIT, ...)` wrapper stays in each caller, because only RelinkDialog reports progress.
