So the `folder` step keeps both buttons and `Закрити` live during that gap. The neighbours set the busy step on their first line, also when a folder picker follows (`ExportDialog.tsx:60`, then `export.ts:116`; `ArchiveDialog.tsx:57`). A second click starts a second `finish`. With a folder, the second run finds the first run's files and writes `land-1-2.jpg` copies when the bytes differ, for example a file that is still being written. `onReplace` then runs twice, so one autosaver is never disposed. - `should-fix` — **`src/ui/ArchiveOpenDialog.tsx:46`, `:52`** — `nameKey` and `freeName` copy `src/storage/archive.ts:63` and `:66`, with the same `-2`, `-3` rule and the same "stays reserved" use. The one real difference is that the dialog returns a free name as it is, while `archive.ts` always adds a suffix.
  → Export both from `archive.ts`, which this file already imports for `crc32OfBlob`. Delete the local copies and keep only the difference here: `taken.has(nameKey(n)) ? freeName(n, taken) : n`.
- `should-fix` — **`src/ui/ArchiveOpenDialog.tsx:13`, `:86`** — `WRITE_SLICE_BYTES` and `writeInSlices` repeat `src/ui/ArchiveDialog.tsx:14` and `:123-138`: the same 1 MB loop, the same `close`, and the same `abort` with the same two comments.   → Move one `writeInSlices(handle, blob, onBytes)` to `src/storage/archive.ts`, and call it from both dialogs. It takes a handle whose `createWritable()` returns `write`, `close` and `abort`, which both call sites have. `ArchiveDialog` keeps its first `setState({ step: 'writing', done: 0, ... })`, and its outer `try` still catches a failed `createWritable`.
